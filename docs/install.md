# Установка тестовой сборки

Как поставить сборку на устройство, обновить её, что с подписью и где лежит ключ. Подготовка сборки не означает публикацию: карточка, модерация и релиз в RuStore — отдельное решение владельца.

## Откуда берётся APK

- **Debug из CI.** Каждый PR и каждый push в `main` собирают `app-debug.apk` и кладут его в артефакт `colabike-debug-<sha коммита>` (вкладка Actions, job `verify`, хранится 14 дней). Он годится, чтобы посмотреть и проверить экраны. Подписан временным ключом отладки раннера, который у каждого запуска свой.
- **Release без подписи** (`./gradlew :app:assembleRelease`, R8) — проверка сборки, а не файл для установки: Android не ставит неподписанный APK. Job `release` в CI собирает его на каждом PR, проверяет выравнивание нативных библиотек под страницы 16 КБ и сохраняет `mapping.txt`.
- **Подписанный release-кандидат** собирает владелец своим ключом (раздел «Подпись» ниже). Агент и CI его не делают: ключа в репозитории и в secrets нет.

## Установка

1. Скачайте артефакт `colabike-debug-<sha>` с вкладки Actions (нужен вход в GitHub), распакуйте архив: внутри `app-debug.apk`.
2. На телефоне: «Настройки → Приложения → Особый доступ → Установка неизвестных приложений», разрешите установку из того приложения, которым открываете файл.
3. Откройте `app-debug.apk` или поставьте с компьютера: `adb install app-debug.apk`.
4. Сервисы Google не нужны ни для установки, ни для работы: приложение запускается на устройствах без них (проверяется на эмуляторе AOSP, см. [приёмку](acceptance.md)).

## Обновление поверх установленной сборки

Android обновит приложение, только если у новой сборки **тот же ключ подписи** и **versionCode не меньше** установленного.

- Debug-сборки из CI подписаны ключом, который у каждого запуска раннера новый, поэтому поверх предыдущей debug-сборки они не встают: сначала удалите приложение (`adb uninstall ru.colabike.app` или «Удалить» в настройках). На устройстве хранится только сессия устройства (зашифрованный refresh-токен) и настройки, остальное лежит на сервере, поэтому терять нечего. Сессия удалённого приложения останется в списке «Устройства и входы» на сайте: завершите её оттуда.
- Сборка release-кандидата от владельца обновляется поверх предыдущей, пока ключ тот же, а `versionCode` растёт.

## Версии

- `versionName` лежит в `app/build.gradle.kts` (сейчас `0.1.0`), его показывает экран «О приложении».
- `versionCode` по умолчанию 1. Для сборки, которую раздают, владелец задаёт `-Pcolabike.versionCode=N`, каждый раз больше прежнего; после установки номер сборки виден на экране «О приложении» рядом с версией контракта API.
- Приложение сообщает в `User-Agent` свою версию (`ColaBike-Android/<версия>`), по ней сервер отличает сборки.

## Подпись

- Release keystore и пароли хранит владелец **вне Git**. В репозиторий, secrets CI и логи они не попадают; `keystore.properties` в `.gitignore`.
- Для App Link (вход через Яндекс ID, ссылки `colabike.ru/app/auth`) сайт должен знать отпечаток сертификата той сборки, которую ставят: `scripts/cert-fingerprint.sh <apk|keystore>` печатает публичный SHA-256, его записывают в `ANDROID_CERT_SHA256` на сайте ([cola, развёртывание](https://github.com/grayhex/cola/blob/main/docs/operations/deployment.md)). Отпечаток ключа отладки добавляют осознанно и временно: debug-сборки CI, ключ каждый раз новый, к App Link не подходят.
- Подписанный APK проверяется так: `apksigner verify --print-certs app-release.apk`, отпечаток сверяется с тем, что записан на сайте.

## Диагностика

На экране «О приложении» видны версия, номер сборки и версия контракта API; сбой сервера показывает код для поддержки (`X-Request-ID`). Эти данные безопасно прислать в обращении: паролей, токенов и переписки в них нет. Расшифровать стек сбоя release-сборки помогает `mapping.txt` той же сборки.

- В CI он лежит в артефакте `colabike-release-mapping-<sha>` (30 дней). Репозиторий публичный, поэтому артефакты видны любому вошедшему в GitHub; для неподписанной сборки открытого кода это не секрет.
- **Mapping подписанного release-кандидата** хранит владелец рядом с ключом, в закрытом хранилище, а не в публичных артефактах. Без mapping из такой сборки стек не прочитать, поэтому его сохраняют при каждой раздаче.
- Внешний crash- или analytics-SDK не подключён и автоматически подключаться не будет.
