# ADR 0012. Каталог компонентов

Статус: принято в рамках [issue #9](https://github.com/grayhex/colabike-android/issues/9), 04.10.2026, первый из двух PR (второй — рынок, сохранённое и контакт продавца). Опирается на [ADR 0004](0004-bikes-search-like-and-page.md) (карточка велосипеда и его комплектация), [ADR 0007](0007-comments.md) (общие комментарии) и [ADR 0002](0002-visual-direction-and-shell.md) (навигация).

## Что решено

- **Читается только публичный каталог API v1:** `GET /component-models` (`q`, `category`, `brand`, `sort`, `limit`, `cursor`), `GET /component-models/filters`, `GET /component-models/{id}` и `GET /component-models/{id}/photos`. Всё доступно гостю, сессия не нужна. Категории и бренды для фильтров берутся с сервера, своего справочника в приложении нет.
- **Вход.** Из раздела «Велосипеды» (значок «Каталог компонентов» в верхней панели) и из комплектации велосипеда или записи журнала: строка компонента, у которого владелец выбрал модель (`modelId`), открывает страницу этой модели целиком; строки без модели не нажимаются. Новой вкладки нижней панели нет.
- **Каталог.** Поиск делает сервер (название, бренд и прежние написания) после паузы 400 мс; порядок «Новые» или «Популярные»; категория и бренд — меню со значениями сервера (повторный выбор снимает фильтр). Любое изменение запроса начинает список заново и отменяет запрос в пути: курсор одного порядка в другом сервер отвергает (400). Страница курсора, в которой модель уже была показана, её не повторяет (порядок «Популярные» меняется между страницами, и сервер прямо предупреждает о повторах и пропусках). Фильтры не загрузились — список работает без них, они приходят с обновлением.
- **Страница модели.** Название, бренд, категория, число публичных велосипедов («На 42 велосипедах»), описание, галерея (тот же просмотрщик, что у велосипеда), обсуждение и ссылка на страницу на сайте (только если путь из ответа — путь этого сайта, `SiteLinks.pageFromPath`). Слитая модель отвечает канонической: её `id` используется для фотографий и обсуждения, а не тот, по которому пришли. Архивная читается и помечена («её нет в каталоге, страница осталась по ссылке»). Неопубликованная и неизвестная — «Модель не найдена» без повтора, потому что повтор ничего не изменит; другие сбои — ошибка с повтором. Не-UUID идентификатор (ссылка может нести что угодно) — «не найдена» без запроса.
- **Чего на странице нет, потому что нет в ответе.** Установок, владельцев, приватных дат, цен и сборок: страница модели не вторая модель пользовательской комплектации.
- **Авторство фотографий показывается так, как отдал сервер.** Загруженное — «Загрузил(а): имя»; фото из внешнего источника — подпись `credit`, провайдер и лицензия, ссылки на источник и на текст лицензии. Ссылка открывается в браузере только если это `https` (`javascript:` и `http:` не предлагаются). Если фотографии не прочитались, страница остаётся без галереи (обложка из карточки, если есть) и не превращается в ошибку.
- **Обсуждение.** Общий экран комментариев ([ADR 0007](0007-comments.md)) с видом `component`: свои правки и ответы, идемпотентный ключ, тот же счётчик. Число комментариев модели API не даёт, поэтому на строке «Комментарии» его нет.

## Чего нет

- Поиска подсказок `GET /search/components` (названия компонентов публичных велосипедов): это другая выдача (по именам из комплектаций, без страницы модели) и отдельный экран «Поиск» в этот срез не вошёл.
- Входа в каталог из экрана «Поиск» и из ссылок `colabike.ru/components/…`: роутер ссылок знает только формы адресов, перечисленные в [ADR 0003](0003-account-guest-and-web-flows.md); формат адреса страницы модели в контракте не описан (есть только относительный `path`), и угадывать его нельзя. Страница модели открывается из приложения.
- Сравнения моделей, избранного моделей и публикации новых (нет операций в API).
