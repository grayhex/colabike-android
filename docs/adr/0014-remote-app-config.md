# ADR 0014. Удалённая конфигурация приложения

Статус: принято в рамках [issue #14](https://github.com/grayhex/colabike-android/issues/14), 04.10.2026, в двух PR: первый — данные, кэш, флаги функций, политика версий, сервисные ссылки; второй — экран запуска, знакомство, сообщение и экраны обновления. Контракт — [`docs/modules/mobile-app.md`](https://github.com/grayhex/cola/blob/main/docs/modules/mobile-app.md) бэкенда ([cola#338](https://github.com/grayhex/cola/issues/338)). Опирается на [ADR 0002](0002-visual-direction-and-shell.md) (оболочка) и [ADR 0003](0003-account-guest-and-web-flows.md) (ссылки и гость).

## Что решено

- **Что приходит.** `GET /api/v1/app-config`: без входа, одинаково для всех, с `ETag` и `max-age=60`. Только данные и доступность того, что уже есть в APK; ни разметки, ни стилей, ни кода. Запрос идёт без сессии.
- **Контракт.** Снимок `api/openapi.json` обновлён из `main` бэкенда (там `/app-config` уже есть, production его пока не отдаёт): `./gradlew :core:network:updateApiContract -PcontractUrl=file:///…`, документ собран из исходников бэкенда (`buildOpenApiDocument`); разница со снимком — только `/app-config`, его восемь схем и два абзаца описания. Пока бэкенд не выложен, еженедельный `checkApiContractDrift` красный: это правда, а не поломка. Клиент не ломается об отсутствие эндпоинта (404 — «ничего нового»).
- **Модель.** `AppConfig` в `core:model` (экран запуска, знакомство, сообщение, служебные ссылки, флаги, совместимость) и `AppConfigRepository`; сгенерированные DTO дальше `core:network` не уходят. Встроенная конфигурация `AppConfig.Builtin`: всё включено, ничего не объявлено.
- **Что приложение не берёт с сервера на веру** (маппер): картинки — только пути сайта (`/…` без `//`, `.` и `..`, тот же scheme/host/port, без логина), размер выбирается приложением (`?width=1920` для экрана запуска, `1280` для карточек); ссылки и кнопки сообщения — только `https` без логина и пароля; ключи функций — только известные приложению, остальные отбрасываются; неизвестный вид сообщения — `promo`, режим картинки — `crop`, режим обновления — `soft`; `hard` без минимальной версии или без адреса — `soft`; экран запуска без картинки сайта выключен; карточек знакомства не больше шести, без заголовка пропускается.
- **Кэш.** Последний ответ лежит в `filesDir/app-config/app-config.json` (резервное копирование выключено): версия формата, `ETag`, время, когда сервер последний раз подтвердил этот ответ, и сам ответ. Пишется во временный файл и переименовывается; повреждённый, пустой, чужого формата или не читаемый этой сборкой — не кэш, его удаляют, приложение идёт на встроенных значениях. Ни токенов, ни данных человека там нет, поэтому выход из аккаунта кэш не трогает.
- **Атомарность.** Новая редакция принимается целиком: ответ прочитан и проверен, картинки скачаны (`FileConfigAssets`: папка `app-config/assets` отдельно от кэша изображений, который уходит вместе с аккаунтом; только с сайта, только `image/*`, не больше 8 МБ, клиентом без сессии, имя — SHA-256 адреса), и только потом запись. Не скачались — остаётся прежняя редакция с прежним `ETag`, следующий запуск спросит снова. После записи картинки, которых новая редакция не называет, удаляются.
- **Холодный старт.** Ничего не ждёт сети: контроллер читает кэш (не дольше двух секунд, любой сбой — «ничего нет»), приложение стартует на нём, и только потом идёт запрос. Оболочка ждёт именно эту короткую выдачу, чтобы вкладки не менялись под руками. Запрос — при старте и при возврате в приложение, не чаще раза в 10 минут, один за раз; `304` продлевает срок кэша, ошибка, офлайн, 5xx, нечитаемый ответ ничего не меняют.
- **Флаги функций** (`FeatureAvailability`: `chat`, `market`, `componentCatalog`, `rides`, `bikeEditor`, `journalEditor`, `nativeYandexSignIn`). Не упомянутая функция включена. Флаг только прячет то, что есть: `true` ничего не создаёт и не открывает закрытое — права проверяет API. Вкладки «Покатушки» и «Сообщения» берутся из конфигурации на момент запуска (вкладка не исчезает из-под человека; выключенная пропадёт при следующем запуске), «Объявления», «Каталог компонентов» и «Сохранённые объявления» в профиле показываются по живому флагу. Экран выключенной функции не открывается ниоткуда — ни по ссылке, ни из уведомления, ни из строки: `Navigator` проверяет флаг при каждом открытии и вместо экрана показывает «Пока недоступно», человек остаётся на месте. `bikeEditor` и `journalEditor` приняты, экранов за ними пока нет. `nativeYandexSignIn` — второй замок к уже существующим: кнопка видна, только когда сборка (`colabike.yandexSignIn`) и сервер готовы и сервер не выключил её.
- **Служебные ссылки.** «Справка», «О проекте», «Условия» и «Политика» берутся с сервера, а без них — свои страницы сайта (`/about#guide`, `/about`, `/legal/terms`, `/legal/privacy`); «Поддержка» своего умолчания не имеет, без ссылки строки нет. Открываются в браузере.
- **Политика версий.** `Compatibility.updateState(versionCode, validatedAt, now)`: ниже `latestVersionCode` — ненавязчивое предложение (`Available`), ниже минимума — `Required` при `hard` и `Recommended` при `soft`. Закэшированному `hard` верят сутки после последнего подтверждения сервером (`HARD_UPDATE_TTL`): откат на сервере или долгая недоступность не запрут человека в приложении навсегда, блок смягчается до настойчивого предложения; время подтверждения из будущего (часы отведены назад) не верится. Экраны этой политики — в разделе «Что видит человек» ниже.
- **Заодно найдено и исправлено.** `Navigator.go` умел открывать только велосипед и человека, поэтому ссылки `colabike.ru/j/…`, `/r/…` и `/market/…` из внешних приложений тихо ничего не делали. Теперь он открывает записи журнала, объявления и модели над «Велосипедами», покатушки — в «Покатушках», разговор — в «Сообщениях».

## Что видит человек (второй PR)

- **Порядок на старте.** Пока читается кэш, пустой фон (не дольше двух секунд, сеть не ждём). Дальше: `Required` → только экран «Нужно обновить приложение»; восстановление сессии → пустой фон; знакомство, если оно включено и его редакция не просмотрена; вход / гость / оболочка. Знакомство показывается до входа и после выхода одинаково: это про приложение, а не про аккаунт.
- **Экран запуска.** После системной заставки: картинка с сервера на всё окно (`fit` или `crop`) и необязательная подпись. Показывается только если картинка **уже лежит на устройстве** (`ConfigAssets.fileOf`): первый запуск после публикации идёт без неё, ничего не скачивается и не ждётся. Закрывается, как только старт готов (кэш прочитан, сессия восстановлена), и не позже чем через 1,5 с; минимального времени «для красоты» нет. Не часть содержимого: не принимает касаний, TalkBack слышит только название приложения. Закрывшись, до конца запуска не возвращается (в том числе после поворота).
- **Знакомство.** Страницы по порядку (`HorizontalPager`): картинка (если скачана), заголовок и текст; раскладка своя, сервер даёт слова и картинки. «Пропустить» и «Начать» одно и то же для человека, оба запоминают просмотренной **редакцию** (`onboarding_seen`): новая редакция показывается снова, старая — нет. Back с второй страницы и дальше возвращает на предыдущую, с первой выходит из приложения. Длинный текст и крупный шрифт прокручиваются.
- **Сообщение.** Одна полоса над содержимым, не блокирует ничего. Вид задаёт громкость: `promo` — тихая («Новости»), `service` — обычная, `maintenance` — самая заметная («Технические работы», объявляется TalkBack). Крестик запоминает **редакцию** (`notice_closed`): изменённое сообщение возвращается. Кнопка идёт через тот же разбор адреса, что и внешние ссылки: страница приложения открывается внутри (выключенная функция — «Пока недоступно»), другая страница сайта и любой `https` — в браузере, остальное не открывается.
- **Предложение обновиться.** Над содержимым тоже, но только одна полоса за раз: настойчивое предложение (`Recommended`, ниже минимума при `soft`) важнее сообщения, сообщение важнее тихого предложения (`Available`). «Позже» у тихого запоминает версию, до которой предлагали (`update_offer_closed`: к следующей новой версии предложение вернётся); у настойчивого — только до закрытия приложения, потому что оно про то, что скоро перестанет работать.
- **Экран «Нужно обновить приложение».** Заменяет приложение целиком: что случилось (текст сервера или встроенный), «Обновить» (адрес из конфигурации, только `https`), «Проверить снова» — немедленный запрос конфигурации (`refreshNow`, не по 10-минутному ограничению), с индикатором и сообщением, если проверить не удалось. Снял блок сервер — экран исчезает сам. Блок смягчается через 24 ч без подтверждения сервером (см. выше).
- **Что запоминается и где.** Три числа в настройках приложения (`onboarding_seen`, `notice_closed`, `update_offer_closed`); ни токенов, ни данных человека. Выход из аккаунта их не трогает.

## Чего нет

- Мгновенного показа картинок первой редакции: они скачиваются вместе с принятием редакции, поэтому экран запуска и картинки знакомства появляются со следующего запуска.
- Проверки на устройстве: TalkBack, поведение экрана запуска вместе с системной заставкой Android 12+ (в тестах — Robolectric и ручные часы).
- Живой проверки: production пока не отдаёт `/app-config`, а тесты идут на MockWebServer и фикстурах; цепочка «администратор поменял — приложение подхватило» проверяется вручную после выкладки бэкенда.
- Удалённой темы, раскладки или кода, Firebase Remote Config, A/B-тестов — это не входит и не будет.
