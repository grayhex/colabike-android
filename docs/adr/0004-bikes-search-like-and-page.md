# ADR 0004. Велосипеды: поиск, лайк и полная карточка

Статус: принято в рамках [issue #5](https://github.com/grayhex/colabike-android/issues/5), 03.10.2026, первый из двух PR (гараж и карточка; люди, поиск людей и подписки — следующий). Дополняет [ADR 0003](0003-account-guest-and-web-flows.md).

## Что решено

- **Поиск и фильтры — это запрос, а не состояние списка.** `BikeQuery` (область «все / мои», текст, типы) целиком уходит в `GET /bikes`. Любая смена запроса отменяет запрос в пути и начинает список заново без курсора, поэтому страница прежнего запроса не может приклеиться к новому; ввод ждёт 400 мс после последней клавиши. Поиск идёт по `q` самого `/bikes` (название, бренд, модель, имя автора). Расширенный `/experience/bikes` (подтип, подвеска, компонент) не нужен для первого поиска и подключается вместе с поиском людей. Нет сети при поиске — ошибка с повтором того же поиска, а не пустой каталог; ошибка следующей страницы оставляет найденное.
- **Лайк — переключатель, а итог говорит сервер.** `PUT` и `DELETE` идемпотентны и возвращают итоговое состояние. Сердце меняется сразу (оптимистично), ответ сервера заменяет догадку, отказ возвращает прежнее сердце и объясняет. Свои и приватные велосипеды не лайкаются: счётчик виден, переключателя нет. Гость при нажатии приходит ко входу, лайк за него потом не ставится.
- **Список и карточка согласуются без перезагрузки.** `BikesRepository.likeChanges` объявляет каждый прошедший лайк, ViewModel списка и карточки меняют только затронутый велосипед.
- **Карточка показывает только то, что даёт контракт.** Цена приходит, когда её видно зрителю (владелец или владелец показывает), и тогда показывается, иначе блока нет. Компоненты идут в порядке владельца (`groupOrder`, затем `sortOrder`), ссылки только `https`. Оценки `scores` не показываются: контракт не определяет, что они значат для человека.
- **Галерея и просмотр на весь экран.** Страницы с счётчиком «2 / 5»; просмотр — отдельное окно с масштабом (щипок, двойное касание) и закрытием; фото запрашивается крупнее (`?width=1600`). Фото, которое не загрузилось (удалено, нет доступа, нет сети), заменяется плиткой «Фото недоступно», а не пустой серой коробкой. Приватные фото получают `Authorization` только на хост сайта, кэш картинок очищается при выходе.
- **«Поделиться»** — системное меню с названием и адресом `/b/<uuid>`, который сайт перенаправляет на канонический. Канонический адрес приложение построить не может (в API нет `publicId`/`slug`), это пробел из ADR 0003.
- **Живой smoke ничего не пишет.** Лайк и подписка меняют боевой аккаунт, поэтому проверяются только тестами с MockWebServer и фейками.
