# ADR 0003. Аккаунт: гость, устройства и то, что остаётся на сайте

Статус: принято в рамках [issue #4](https://github.com/grayhex/colabike-android/issues/4), 03.10.2026, два PR: аккаунт и устройства; ссылки, router и жизненный цикл сессии. Дополняет [ADR 0001](0001-platform-baseline.md) и [ADR 0002](0002-visual-direction-and-shell.md).

## Что решено

- **Гость — выбор на первом экране.** Без сессии приложение показывает вход с кнопкой «Смотреть без входа». Выбор хранится в настройках устройства и живёт до входа: после выхода приложение спрашивает снова, а не оставляет человека «гостем» против его воли. Гость видит публичное (велосипеды), но не «Мои», а всё, что требует аккаунта, открывает вход поверх его места.
- **Одна оболочка на гостя и участника.** `AppShell` не пересоздаётся при входе гостя: навигация и положение прокрутки сохраняются (`SaveableStateProvider`), поэтому человек возвращается туда, откуда пришёл. ViewModel привязаны к зрителю (`Viewer.Guest`/`Viewer.Member`) и сбрасываются при его смене: данные гостя не остаются в сессии участника. После выхода оболочка начинается заново.
- **Не выполнять за человека.** Вход возвращает на место, но не повторяет действие: записывающих действий в приложении пока нет, а когда они появятся (лайк, комментарий, контакт), они требуют подтверждения после входа. Это правило записано здесь, чтобы следующие срезы его не нарушили.
- **Чего нет в API v1, остаётся на сайте.** Контракт содержит вход, обновление, список и завершение сеансов, `/me`, но не регистрацию, восстановление пароля, подтверждение и смену почты, смену пароля и удаление аккаунта (проверено по снимку контракта и документации сервера, [cola docs/modules/accounts.md](https://github.com/grayhex/cola/blob/main/docs/modules/accounts.md)). Приложение открывает эти страницы сайта в Custom Tabs с подписью «открывается в браузере» и не передаёт туда токен. Нативные заменители не имитируются; редактирование профиля без write-контракта не добавляется.
- **Устройства.** `GET /auth/sessions` показывает это устройство первым и с пометкой, остальные можно завершить после подтверждения. Свой сеанс отзывается только выходом, который заодно чистит локальные данные. Сеанс, которого на сервере уже нет (404), просто исчезает из списка.
- **Тема хранится в SharedPreferences**, а не в DataStore: два значения не оправдывают новой зависимости. Секретов в этом хранилище нет.
- **Яндекс ID остаётся выключенным.** На production `/.well-known/assetlinks.json` пуст (нет отпечатка сертификата), а `https://colabike.ru/app/auth` отвечает 404: App Link не подтверждён, пока владелец не задаст `ANDROID_CERT_SHA256` и `NATIVE_AUTH_RETURN_URL` ([cola#324](https://github.com/grayhex/cola/issues/324)). Кнопка скрыта флагом `-Pcolabike.yandexSignIn`, который остаётся по умолчанию выключенным.

## Ссылки и router (второй PR)

- **Разбор по allowlist** (`AppLinkParser`). Данные Intent недоверенные: принимается только `https`, хост сайта, порт по умолчанию, без логина и пароля, и только формы адресов самого сайта ([public-urls](https://github.com/grayhex/cola/blob/main/docs/modules/public-urls.md)). Query и fragment не читаются. В `AppLink` попадают типизированные значения (UUID в нижнем регистре, username по шаблону), а не исходная строка. Всё остальное, включая другие схемы (`intent:`, `file:`, `content:`, `javascript:`), — `NotForTheApp`. Intent целиком никуда не передаётся и не запускается (skill `android-intent-security`).
- **Что открывается в приложении.** Сейчас у приложения есть экран только велосипеда: `/b/<uuid>` открывает его. Журнал, покатушка, объявление и профиль по `/j/…`, `/r/…`, `/market/…`, `/@username` пока ведут на сайт по тому же адресу; когда срез добавит экран, меняется одна ветка `AppLink.target`.
- **Адреса с публичным id** (`/b/<slug>-<id>`) — **пробел API**: в контракте v1 нет ни `publicId`/`slug`, ни способа превратить их в UUID, а приложение его не угадывает. Такой адрес уходит на сайт, пока на сервере не появится разрешение (запрос к владельцу сервера записан в очереди #2).
- **Ожидаемый переход** (`PendingNavigation`). Ссылка, которую нельзя выполнить сразу (вход на экране, холодный старт, браузер Яндекса), хранится на устройстве до 30 минут и выполняется, когда оболочка на экране: она выбирает раздел «Велосипеды», открывает велосипед, «назад» ведёт на список. Хранится только то, что ссылка может открыть, и только целым и свежим. Записывающие действия по ссылке не выполняются никогда.
- **Intent-filter объектов пока нет.** В манифесте только `/app/auth`. Фильтр на `/b/*` и другие пути добавляется вместе с разрешением публичных id: иначе проверенная ссылка, которую приложение не умеет открыть, уходила бы «на сайт» обратно в приложение.
- **Не найден, удалён, приватный.** Сервер отвечает всем 404, поэтому экран говорит «Не нашли…»; гость дополнительно видит «Если это приватный велосипед, войдите в свой аккаунт» с кнопкой входа, после которой он возвращается на то же место.
- **Яндекс ID и App Link.** Возврат принимается только на `https://colabike.ru/app/auth` без порта и дополнительного пути; посторонние ссылки не трогают ждущий verifier, повторная ссылка не находит ничего, вход при уже открытой сессии игнорируется. Сертификат для `assetlinks.json` берётся из подписи устанавливаемой сборки: `scripts/cert-fingerprint.sh` печатает его SHA-256 для `ANDROID_CERT_SHA256`. Ключ отладки в список сервера по умолчанию не добавляется.
- **Жизненный цикл сессии.** Подтверждено тестами: сбой сервера (5xx), ограничение (429) и обрыв связи при обновлении не стирают действующую сессию (токен не расходуется, следующий запрос восстанавливается); окончательный `invalid_token` ведёт ко входу; кэш картинок очищается только при выходе человека, а не при старте без сессии (гостевые картинки переживают перезапуск).

## Пробелы API, найденные в #4

1. Разрешение публичных id (`/b/<slug>-<id>`, `/j/…`, `/r/…`, `/market/…`) в UUID API.
2. Регистрация, восстановление пароля, подтверждение и смена почты, смена пароля, удаление аккаунта в API v1 (работает на сайте).
3. Конфигурация Яндекс ID: `ANDROID_CERT_SHA256` и `NATIVE_AUTH_RETURN_URL` на production (cola#324).

## Что проверено и что нет

Проверено юнит- и Robolectric-тестами, MockWebServer и скриншотами (обе темы, compact/expanded, шрифт 200 %); live smoke на эмуляторе в CI теперь заходит и на экран устройств (`/auth/sessions`). Не проверено: настоящие App Link и Яндекс ID (блокирует конфигурация сервера выше), TalkBack на железе.
