# ADR 0017. Push: регистрация телефона, адаптер RuStore и чат

Статус: принято в рамках [issue #30](https://github.com/grayhex/colabike-android/issues/30), 05.10.2026, часть 3 из трёх (основа показа — [ADR 0015](0015-push-notifications.md), согласие и настройки — [ADR 0016](0016-notification-settings.md)). Сервер — [cola#342](https://github.com/grayhex/cola/issues/342) (реестр устройств, очередь доставки, транспорт RuStore) и поток Stream → push (cola PR #350, envelope с `target.ref`). Контракт регистрации — `devices.json` из `docs/contracts/notifications/v1` бэкенда, закреплён в `core/network/src/test/resources/contracts/notifications/v1`.

## Что решено

- **Привязка телефона принадлежит сессии приложения, а не токену доступа.** `PUT/GET/DELETE /me/push-device` (`PushDeviceRepository`, генерированный клиент). Тело запроса: `installationId` (случайный UUID этой установки, переживает выход), `provider = rustore`, `projectId`, `token`, `expectedGeneration`. Адрес телефона у провайдера — секрет: он есть только в теле запроса, сервер хранит его зашифрованным и не возвращает, приложение не пишет его ни в журнал, ни в `toString()`, ни в настройки (`PushDeviceRegistration.toString()` называет проект и поколение).
- **Что помнит телефон** (`StoredPushBinding`, SharedPreferences без резервного копирования): аккаунт, поколение привязки, проект, **отпечаток** отправленного адреса (8 байт SHA-256 — чтобы знать «тот же адрес», а не сам адрес), время последней сверки и идентификатор установки. Это же и `PushBinding`, который читает `PushHandler` на каждое сообщение: нет записи или поколение конверта не текущее — ничего не показывается (ADR 0015). Выход из аккаунта стирает запись сразу, без сети (сервер удаляет привязку вместе с сессией).
- **Регистрация следует за выбором человека, а не за запуском** (`PushRegistrar`, одна сверка за раз). Телефон зарегистрирован, пока одновременно: провайдер может доставлять, аккаунт сказал «да» push и сервер его носит (`push.available`), телефон показывает уведомления (`DeviceNotificationsState.canShow`). Перестало выполняться что-то одно — привязка отзывается (`DELETE`). Согласие живёт в настройках аккаунта ([ADR 0016](0016-notification-settings.md)); `getToken` согласием не считается.
- **Когда сверка запускается** (`PushSync.request`): старт приложения (`MainActivity.onStart`), появление сессии с известным аккаунтом, сохранённое изменение в «Профиль → Уведомления», ответ на системный вопрос о разрешении, `onNewToken` провайдера. Вызов дешёвый и безопасный при частых повторах: целая и свежая (моложе 7 дней) привязка **не вызывает ни одного запроса**; старше — повторяется, чтобы сервер видел телефон живым.
- **Поколения и запоздалые ответы.** Регистрация идёт с `expectedGeneration` — поколением, которое телефон считает текущим. На `409` (сервер знает другое) приложение один раз читает привязку (`GET`) и повторяет; второй `409` — сообщение об ошибке, без цикла. Новый адрес, другой проект и привязка после отзыва — следующее поколение; приложение сохраняет ответ сервера и сверяет с ним каждый конверт.
- **Нет сети — ничего не меняется.** Ошибка сети или сервера оставляет прежнюю запись, следующий запуск сверки пробует снова; нечитаемые настройки аккаунта **не принимаются за «нет»** (привязка не отзывается). `SignedOut` стирает запись (сессия ушла вместе с привязкой).

## Адаптер RuStore

- **SDK `ru.rustore.sdk:pushclient:7.5.0`**, репозиторий Maven RuStore (`nexus-external.rustore.ru`) подключён **только для группы `ru.rustore.sdk`** — больше никакой артефакт через него не придёт. Версия закреплена в `libs.versions.toml`; обновление — осознанный PR с проверкой `checkNoPlayServices` и манифеста.
- **Проект владельца** — свойство Gradle `colabike.rustore.projectId` (в `gradle.properties` пользователя или `-P…`, **в репозиторий не попадает**), проверяется по шаблону и становится `BuildConfig.RUSTORE_PROJECT_ID`. Пусто — сборка без провайдера: `NoPushProvider`, push не предлагается, SDK не стартует, разработческая сборка ни с кем не разговаривает. Регистрация в RuStore, ключи и подпись — дело владельца ([docs/install.md](../install.md)).
- **Сервис доставки** `ColaPushService` экспортируется (RuStore привязывается к нему снаружи) и отвечает на одно действие `ru.rustore.sdk.pushclient.MESSAGING_EVENT`. Сообщения — только данные: он берёт `data["envelope"]` и отдаёт `PushHandler`, который проверяет конверт целиком до показа (ADR 0015); чужое и повреждённое не показывается. Новый адрес (`onNewToken`) уходит в регистрацию.
- **Журнал SDK выключен** (`SilentLogger`): его обычный логгер печатает, что делает, а адрес телефона не для системного журнала.
- **Библиотека стартует только при причине.** `RuStorePushClient.init` вызывается (1) в `Application`, если телефон **уже зарегистрирован** (сообщение может прийти в любой момент), и (2) из регистрации **после «да» человека** и разрешения на показ. Человек, который push не включал, SDK не запускает вовсе: у него нет ни работы библиотеки, ни её сетевых запросов. До старта `availability()` отвечает по самому телефону (установлено ли приложение RuStore, пакет `ru.vk.store`), после — по библиотеке (RuStore есть, вошёл ли человек, поддерживаемая версия).

## Что делает SDK сам (проверено разбором байт-кода 7.5.0)

- **Статистика работы SDK** (`ru.rustore.sdk:metrics`): события клиента уходят на `https://stats-dg.rustore.ru` задачей `SendMetricsEventJobService` (период 1440 минут). Отключить её без поломки SDK нельзя; содержимое событий приложением не управляется. Это вторая причина запускать SDK только у тех, кто включил push.
- **Крэш-репортёр Tracer** (`ru.ok.tracer:*`, отчёты на `sdk-api.apptracer.ru`) SDK подключает по имени через рефлексию и при отсутствии библиотеки **переходит на заглушку** (`Using stub crash reporter`, перехват `Throwable`). Приложение **исключает группу `ru.ok.tracer`** из зависимости (`exclude(group = …)`), правило R8 `-dontwarn ru.ok.tracer.**` снимает предупреждение об оставшейся ссылке. `PushSdkTest` проверяет, что классов репортёра нет.
- **Компоненты SDK в манифесте**: `RuStorePushClientInitProvider` (не экспортируется; автозапуск только при метаданных проекта, которых нет), `ArbiterBroadcastReceiver` (**экспортируется**, одно действие `com.vk.push.ACTION_MASTER_HOST_UPDATE`: ставит в очередь работу «обновить главный узел»; без запущенного SDK пишет предупреждение и ничего не делает), `SendMetricsEventJobService` (не экспортируется), блок `<queries>` на `ru.vk.store` и службы VK Push. Разрешение `RECEIVE_BOOT_COMPLETED`, которое просит библиотека метрик, по-прежнему снято в манифесте приложения (`ManifestPermissionsTest`).
- **Ссылка `trk.mail.ru`** в классах SDK — адрес установки RuStore; приложение её не вызывает.
- **Что не проверено и остаётся решением владельца**: состав событий статистики RuStore и поведение SDK на живом устройстве (нужны проект владельца, подписанный APK и RuStore). Если эта цена за доставку неприемлема, push остаётся выключенным: ни приложение, ни inbox от него не зависят.

## Чат

- Конверт Stream → push (cola PR #350) несёт категорию `chat`, тип `chat_message`, цель `type = "chat"` с **`ref`** — идентификатором разговора (`cid`, `тип:id`, не больше 120 знаков; проверяется шаблоном) и без `id`. `eventId` — идентификатор сообщения, а не уведомления.
- Нажатие ведёт прямо в разговор (`Destination.Conversation(cid)`; без `ref` — в список разговоров). **Серверной пометки «прочитано» у чата нет** (непрочитанное хранит Stream), поэтому `PushOpener` её не отправляет. `PendingNavigation` хранит разговор и список разговоров.
- **Сообщение открытого разговора не звенит**: экран разговора, пока он в переднем плане (`LifecycleResumeEffect`), отмечает свой `cid` (`VisibleConversation`, только в памяти), и `PushPolicy` не показывает сообщения этого разговора. Свернули приложение — следующее сообщение показывается.

## Манифест

- Добавлен экспортируемый `.push.ColaPushService` и компоненты SDK выше; `INTERNET`, `POST_NOTIFICATIONS`, `ACCESS_NETWORK_STATE`, `WAKE_LOCK` — как были. Микрофона, камеры, местоположения, автозапуска и foreground-службы по-прежнему нет. Единственные экспортируемые компоненты приложения — `MainActivity`, `ColaPushService` и приёмник SDK (`PushSdkTest`, `ManifestPermissionsTest`).

## Чего нет

- **Живой матрицы** (два аккаунта, подписанный APK, RuStore на устройстве, Doze, перезагрузка, смена аккаунта, ротация адреса): без проекта владельца и подписи её не проверить. Мгновенная доставка на устройствах с ограничениями батареи и после принудительной остановки не гарантируется.
- **Сверки при потерянных сообщениях** (`onDeletedMessages`), **ответа из уведомления** (`RemoteInput`), **тестового уведомления** (`sendTestNotification`) и подписок на темы — отдельными ограниченными PR.
- **«Рядом» и грубого местоположения** — часть 2 задачи #31, **действий над намерениями** — #32; обе против cola#343.
