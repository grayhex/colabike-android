# ADR 0010. Центр уведомлений ColaBike

Статус: принято в рамках [issue #8](https://github.com/grayhex/colabike-android/issues/8), 04.10.2026, первый из двух PR (читаемый inbox отдельным первым PR разрешён задачей); второй — мессенджер на Stream Chat. Опирается на [ADR 0007](0007-comments.md) (обсуждение с `focus`) и [ADR 0003](0003-account-guest-and-web-flows.md) (роутер ссылок).

## Что решено

- **Читается только то, что есть в API v1:** `GET /me/notifications` (страницы по курсору, новые сверху) и `GET /me/notifications/count`. Контракт проверен свежим снимком (`updateApiContract`, diff пуст): **операции «пометить прочитанным» в API нет**. Это backend gap, он записан здесь и в `docs/screen-api-mapping.md`.
- **Без фиктивного «прочитано».** Приложение ничего не помечает и не обнуляет число у колокольчика локально: открытие inbox не меняет серверный счётчик. Экран один раз и прямо говорит об этом («Прочитанными уведомления отмечаются на сайте… число у колокольчика не уменьшается»). Состояние «не прочитано» берётся из `readAt` и показывается точкой и словом «Новое» в озвучке, а не одним цветом.
- **Колокольчик в шапке верхних экранов** (Велосипеды, Лента, Покатушки, Профиль) показывает серверное число. Число спрашивается при возвращении в приложение и при переходах по приложению, не чаще раза в полминуты; сбой запроса оставляет прежнее число (ошибка счётчика — не экран ошибки). `capped` (сервер считает до 100) никогда не выдаётся за точное число: показывается «99+», озвучка — «непрочитанных не меньше ста». Число от 1 до 99 точное. У гостя нет ни колокольчика, ни запросов. Число не смешивается с непрочитанными сообщениями чата (отдельный счётчик во втором PR).
- **Открытый набор видов.** `type` уведомления и `target.type` — открытые строки. Известные виды (`follow`, `like`, `comment`, `reply` и их `ride_*`/`journal_*`/`article_*`, `component_reply`, `market_expiring`, `session_reuse`, `bike_week`) получают свой заголовок; неизвестный получает общий вид «Новое событие» с названием объекта и по-прежнему открывается.
- **Переход идёт по типизированному `target`, а не разбором пути:** `bike`, `ride`, `journal` открывают свой экран, `profile` — страницу человека, `account` с `session_reuse` — «Устройства». Для уведомления о комментарии (`comment`, `reply`, `*_comment`, `*_reply`) путь несёт якорь комментария: берётся первый UUID фрагмента (как бы ни назывался якорь), и открывается обсуждение на этом комментарии (сервер возвращает ветку и цепочку, [ADR 0007](0007-comments.md)). Формат якоря в контракте не описан, поэтому читается терпимо; нет якоря — открывается сам объект. Всё остальное (`market`, `article`, `component`, `bike-week`, неизвестные типы) открывается на сайте по пути из `target.path`, и только если это путь на хосте сайта (`SiteLinks.pageFromPath`: один `/` в начале, без управляющих символов и `\`, тот же `https`-хост и порт); иначе строка не нажимается.
- **Удалённый или закрытый объект** открывается в обычное «не найдено» своего экрана, прежнего приватного содержимого нет (сервер сам не показывает уведомления о том, что получатель уже не вправе видеть).
- **Роутер ссылок обновлён:** адреса `/j/<uuid>` и `/r/<uuid>` теперь ведут на экраны журнала и покатушки, а не на сайт (экраны появились в #6 и #7).
- **Чтение inbox на сервере** создаёт напоминание о конце срока объявления (раз за срок), как и на сайте; приложение не делает лишних чтений: страницы по курсору, обновление жестом.

## Чего нет

- Пометки «прочитано» (нет операции), push-уведомлений (не входят в эту задачу и не подключаются автоматически: ни FCM, ни GMS; канал выбирается отдельно с учётом RuStore), группировки и фильтров.
- Реальных тестовых аккаунтов в живом smoke: он читает только списки и страницы; inbox проверяется на фейках и MockWebServer.
