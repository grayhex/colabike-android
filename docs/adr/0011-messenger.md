# ADR 0011. Мессенджер на Stream Chat

Статус: принято в рамках [issue #8](https://github.com/grayhex/colabike-android/issues/8), 04.10.2026, второй из двух PR (первый — [центр уведомлений, ADR 0010](0010-notifications-inbox.md)). Опирается на [ADR 0002](0002-visual-direction-and-shell.md) (тема и навигация), [ADR 0003](0003-account-guest-and-web-flows.md) (гость, устройства, ссылки на сайт) и [ADR 0005](0005-people-follow-and-search.md) (страница человека).

## Что решено

- **SDK.** Официальный `io.getstream:stream-chat-android-compose` 7.13.0 (стабильный релиз, не alpha), версия закреплена в `gradle/libs.versions.toml`. Мост ColaBike (cola#324) выдаёт именно токены Stream, поэтому другой клиент не подходит. Всё, что касается SDK, лежит в `app/.../messages`; остальное приложение знает только интерфейсы `ChatRepository` (`core:model`), `ChatGateway` и `ChatScreens`.
- **Куда что ходит.** Сообщения идут между SDK и провайдером напрямую; приложение их не хранит, не копирует и не пишет в лог. ColaBike API получает только четыре запроса моста: `POST /chat/token`, `POST /chat/channels`, `GET /chat/people`, `GET /chat/unread` (репозиторий готов, на экране числа пока нет, см. «Чего нет»).
- **Токен.** Первый токен берётся из `POST /chat/token` (живёт 5 минут, публичный ключ приложения, секрета нет). Когда SDK находит токен истёкшим, он просит новый у `TokenProvider`, а тот ходит к мосту обычной сессией устройства; не удалось — пустая строка (контракт SDK), подключение падает в «повторить». `ChatCredentials.toString()` не содержит ни токена, ни ключа. Уровень логов SDK — `NOTHING`. Хранилище учётных данных SDK заменено на память (`MemoryCredentials`): по умолчанию SDK пишет id и токен в SharedPreferences ради push, а push здесь нет.
- **Жизненный цикл.** `ChatSession` (`Off → Connecting → Connected | Failed`). Подключение ленивое: при первом показе экрана чата, не при запуске и никогда для гостя. Повтор после сбоя — по кнопке. Выход и смена аккаунта (`AppGraph` на `signOuts()`) вызывают `end()`: отмена подключения, `disconnect(flushPersistence = true)`; SDK забывает базу и сессию этого человека, следующий аккаунт ничего не находит. В фоне SDK сам закрывает сокет по жизненному циклу процесса и поднимает при возвращении. Нет ни foreground-сервиса, ни периодического опроса, ни push (FCM/GMS не подключаются).
- **Каналы создаёт только сервер.** Встроенное «начать чат» SDK не показывается (`onStartChatClick = null`). Новый диалог и группа — `POST /chat/channels`: сервер решает, кому можно писать (404 — «этому человеку нельзя написать»: себе, заблокированному, без подтверждённой почты). Диалог открывается повторно тем же каналом. Группа — от 2 до 7 людей и название до 80 знаков (то же проверяется до запроса); повтор запроса с тем же составом и названием уходит с тем же `Idempotency-Key`, поэтому потерянный ответ не порождает вторую группу. Список диалогов — только каналы типа ColaBike, где человек участник.
- **Люди.** Без запроса — те, на кого подписан человек; с запросом от двух знаков (после паузы 400 мс) — поиск сервера, до 20. На странице другого человека есть «Написать»: открывает его диалог; гостю предлагается войти.
- **Отказы в словах.** Почта не подтверждена (403 `email_verification_required`) — «сообщения закрыты» и ссылка на аккаунт на сайте; чат выключен или провайдер недоступен (503) — «сайт работает, попробуйте позже»; нет сети — общая ошибка с повтором; всё остальное — через `toUiText()`. Гость вместо раздела видит объяснение и вход.
- **Что выключено в SDK** (`colaChatConfig`): перевод сообщений, голосовые сообщения, предпросмотр ссылок, закрепление, отключение звука и блокировка (кому писать, решает сервер; блокировка человека делается на его странице и доходит до провайдера с сервера). Жалоба на сообщение включена с [ADR 0021](0021-account-deletion-and-safety.md): это то, чего магазины требуют от чата, очередь модерации Stream — у владельца. Вложения — только изображения через системный Photo Picker (`useSystemPicker`, без разрешений на доступ к хранилищу). Без звонков, видео и платной автомодерации.
- **Манифест.** SDK и его зависимости приносят `RECORD_AUDIO`, `READ_MEDIA_VISUAL_USER_SELECTED`, `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`, `FOREGROUND_SERVICE`, foreground-службу WorkManager, провайдер и приёмник push, `PushPermissionsInitializer` (запросил бы разрешение на уведомления при открытии любого экрана) и экспортируемый `PreviewActivity` из Compose tooling (в release он попадает через зависимость SDK). Всё вырезано через `tools:node="remove"`, кроме `POST_NOTIFICATIONS`: с [ADR 0015](0015-push-notifications.md) оно объявлено приложением для собственных push (запрос у человека — только с согласием на push, автозапрос Stream по-прежнему снят); `ManifestPermissionsTest` проверяет итоговый манифест. Проверка Lint `NotificationPermission` больше не отключена: разрешение объявлено (раньше её приходилось гасить в `app/lint.xml`, пока оно было вырезано); а `MissingClass` для вырезаемых классов снят `tools:ignore` на самих элементах (они есть в runtime-пути библиотек, но не в compile-пути).
- **Русский язык.** В SDK нет русского. `values/stream_chat_strings.xml` — 451 строка и 20 plurals (все переводимые ресурсы `compose` и `ui-common` 7.13.0), ключи SDK, тон приложения. Лежат в базовом `values`: приложение русское, а ресурсы приложения перекрывают библиотечные по имени. `StreamStringsTest` падает, если новая версия SDK добавила строку без нашего перевода. `androidResources.localeFilters = ru` убирает из APK десяток чужих языков библиотек. `res/raw/keep.xml` не даёт lint и сжатию ресурсов счесть эти строки неиспользуемыми: SDK читает их по имени.
- **Тема.** Никакого второго стиля: `ColaChatTheme` строит палитру `StreamDesign.Colors` из `MaterialTheme.colorScheme` (светлая и тёмная; тёмный режим определяется по самой схеме, потому что тему выбирает человек), шрифт тот же. Палитра собирается конструктором SDK целиком, а не правится после: иначе производные цвета SDK остались бы прежними. `ColaChatThemeTest` проверяет контраст 4.5 : 1 у основных пар (текст на странице и карточке, на акценте, ссылка, ошибка).
- **Раскладка.** «Сообщения» — список, диалог — деталь (`ListDetailSceneStrategy`, как велосипеды). От 840 dp они рядом, справа заглушка «Выберите диалог»; на телефоне диалог открывается на весь экран, плавающая панель разделов отступает, чтобы не закрывать поле ввода. Новое сообщение — отдельный экран; созданный канал открывается вместо него, «назад» из диалога ведёт к списку.
- **Тесты.** Только фейки и MockWebServer, как везде. `ChatGateway` (подключение SDK) и `ChatScreens` (экраны SDK) подменяются: `FakeChatScreens` рисует настоящие компоненты SDK (строки списка, пузыри, поле ввода) в нашей теме на готовых данных, без клиента, поэтому скриншоты показывают тот вид, который увидит человек. Мост проверяется `MockWebServer` (`ChatRepositoryTest`). Конечный автомат подключения, поиск, диалог, группа, отказы — модульные тесты; весь путь от вкладки до диалога — Robolectric (`MessagesFlowTest`).
- **Лицензия SDK.** Stream Chat SDK распространяется по [Stream License](https://github.com/GetStream/stream-chat-android/blob/main/LICENSE) (Source Code License Agreement): это собственное соглашение Stream, а не открытая лицензия. По тексту: лицензиат должен быть действующим клиентом Stream и не его конкурентом (преамбула, п. 3 и 6); распространять объектный код как часть своего приложения можно (п. 2e), исходный код SDK и свои изменения в нём — нет (п. 3 и 7); п. 4 запрещает использовать открытое ПО так, чтобы SDK подпал под открытую лицензию (копилефта в приложении нет). Это не юридическое заключение: перед публикацией в RuStore владельцу нужно проверить условия на своём аккаунте Stream. Название и ссылка показаны на экране «Лицензии», рядом с BSD 2-Clause MapLibre Native (полный текст в приложении). Провайдер хранит сообщения на своих серверах — это пункт политики конфиденциальности.

## Чего нет

- **Живой обмен двух аккаунтов не проверен автоматически.** Настоящий чат нужен двум подтверждённым аккаунтам и ключам провайдера, а секреты живут только в CI владельца. Отправка, чтение, «печатает», ответ, реакции, картинка и переподключение проверяются вручную по чек-листу из описания PR; в CI SDK не подключается.
- Push-уведомлений чата (нет FCM/GMS; основа показа и перехода — [ADR 0015](0015-push-notifications.md), канал RuStore и сообщения чата ждут cola#342) и значка непрочитанных на вкладке «Сообщения»: плавающая панель не умеет значки, а `GET /chat/unread` сейчас не нужен списку (у каждого диалога своё число). Репозиторий и запрос готовы.
- Ограничения набора реакций, обсуждений в ветках и «печатает/прочитано» на стороне приложения: работает то, что включил на канале сервер и что умеет SDK по умолчанию.
- Звонков, видео, голосовых, файлов (кроме изображений), опросов, переводов, ручного управления участниками группы.
